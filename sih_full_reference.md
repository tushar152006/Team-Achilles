## 3. PROBLEM STATEMENT SELECTION FRAMEWORK

### GREEN FLAGS
- Clearly defined deliverables with measurable outcomes
- Data/APIs publicly available or easily synthesizable
- Niche/specialized domain (fewer competing teams)
- Active government missions (TB Elimination, Jal Shakti, Digital India)
- Demoed live in 45-60 seconds with clear input→output→impact
- Genuine AI/ML innovation (not wrapper)
- Team has domain expertise

### RED FLAGS
- Vague/broad objectives
- No data access (classified/internal datasets)
- Oversaturated domains (generic agriculture, traffic, campus parking, fake news, mental health chatbot)
- Already well-solved in market
- Skills mismatch (hardware PS for software team)
- Too ambitious for 36 hours
- Policy/awareness PS with no crisp technical demo

### Competition Analysis
- "Glamorous" PS = 300+ teams = avoid unless extraordinary edge
- Niche PS from NTRO, ISRO, Ports, Coal India, Jal Shakti = fewer teams, higher win probability

## 4. INTERNAL HACKATHON — THE HARDEST FILTER

### What Evaluators Look For
1. Deep problem analysis (not just reading the title)
2. Innovation (different from first 5 Google results)
3. Clean system architecture diagram
4. Feasibility for 36-hour build
5. Every member can explain full project
6. Working prototype (even basic)

### Winning Formula
Deep Problem Analysis + Clean Architecture + Basic Working Prototype + Polished 5-Slide PPT + Confident Q&A

### Pro Tips (Reddit/YouTube Winners)
- Talk to SPOC early
- Show deployed prototype (GitHub Pages/Vercel/Render)
- Include "Comparison with Existing Solutions" slide
- Practice 3-5 minute pitch
- Have backup video demo

## 5. PPT FORMAT (6-Slide Limit)
| Slide | Content |
|-------|---------|
| 1 | PS ID, Title, Team Name, Members, Mentor |
| 2 | Problem Understanding + statistics |
| 3 | Proposed Solution & Novelty |
| 4 | System Architecture diagram + Tech Stack |
| 5 | Feasibility & Viability (36-hour plan) |
| 6 | Impact & Benefits (quantified metrics) |

### Best Practices
- Visuals > Text, max 6 bullets/slide
- Consistent colors, min 14pt font
- Include deployed prototype/video link
- PDF format, under 10MB

## 6. DEMO STRATEGY

### 90-Second Rule
Input → Processing → AI/Logic → Decision → Visualization → Impact

### Must-Haves
- Realistic Indian data
- Error handling shown
- Mobile responsive
- Dynamic (no hardcoding)
- Clear before/after

### Backup Plans
| Scenario | Backup |
|----------|--------|
| Internet fails | Local database + cached API responses |
| API/Cloud fails | Offline fallback with preloaded data |
| Demo crashes | Pre-recorded 3-min video (MANDATORY) |
| Laptop dies | GitHub + teammate's laptop |

### 5-Minute Pitch Flow
1. Problem (30s) 2. Gaps (30s) 3. Solution (60s) 4. Architecture (60s) 5. Live Demo (90s) 6. Impact (30s) 7. Team (30s)

## 7. COMMON MISTAKES THAT KILL TEAMS

### Technical
- 20 half-broken features instead of 1 killer workflow
- AI/ML as buzzword without understanding
- No error handling / edge cases
- Hardcoded demo data
- No offline fallback
- Over-engineering

### Strategic
- Oversaturated PS
- Not reading PS 10+ times
- Coding before architecture
- All 6 coding, nobody on pitch/demo/docs
- Not practicing Q&A
- Changing PS too late

### Presentation
- Text-heavy slides
- Members can't explain project
- No working prototype
- Exceeding time limit
- No backup demo video
- "The AI generated it" answers

## 9. JUDGE Q&A PREPARATION

### Questions They WILL Ask
- Why is this innovative?
- Why this technology/model/framework?
- Where did training data come from?
- Model accuracy? Baseline comparison?
- What happens when system is WRONG?
- How does it scale to 1M users?
- Deployment cost? Who pays?
- What happens without internet?
- Security and data privacy?
- Why should government adopt this?
- What if sensors/APIs/services fail?
- Real-world validation plan?
- Biggest limitation?
- What happens after the hackathon?

### How to Answer
- Be HONEST about limitations
- Quantitative answers ready
- Reference specific technical decisions
- Show failure mode thinking
- Never "AI does it" without explaining HOW
